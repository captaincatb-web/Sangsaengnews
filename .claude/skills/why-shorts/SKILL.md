# /why-shorts — 시네마틱 설명형 쇼츠

레퍼런스 형식(@WHY.STOPPED류)은 다음과 같다.
- 화면: 주제 현장을 사실적으로 찍은 듯한 AI 영상 컷 16~27개(컷당 1~3초). 핵심 요소에는 네온빛으로 개념을 표시한다(빨강=위험·점유·한계, 노랑=안전거리·주의, 파랑=구간·정상, 주황=속도·에너지, 초록=허용·안전). 카메라는 천천히 전진한다.
- 소리: 빠른 남성 내레이션이 쉬지 않고 이어지고, 배경음악은 작게 깐다.
- 자막: 컷마다 6~15자 한 줄, 흰 글씨에 얇은 외곽선, 화면 64% 높이에 둔다.
- 마무리: 컷 사이 0.3초 크로스페이드, 구석에 작은 채널 워터마크, 끝에 어둡게 처리한 엔딩 카드(채널명).

이 환경에서는 AI 영상을 직접 만들 수 없다(외부 생성 서비스 접속 불가). 그래서 두 단계로 진행한다.
- 1단계: 대본과 컷별 프롬프트를 쓰고, 네온 대체 장면으로 미리보기를 만든다.
- 2단계: 사용자가 Google Flow(Veo)·Kling 등으로 클립을 만들어 올리면 완성본으로 조립한다.

## 1단계: 주제 → 미리보기 + 프롬프트

1. `bash shorts/setup.sh`로 설치를 확인한다(이미 설치돼 있으면 몇 초).
2. spec을 `output/why/<영문-슬러그>.json`에 쓴다. 형식은 `shorts/why_example.json`과 같다.
   ```json
   {"topic": "주제(질문형)", "handle": "@채널", "accent": "red",
    "style": "모든 컷에 공통으로 붙일 장소·소품 묘사(영어)",
    "lines": [{"cuts": [{"text": "자막 한 줄", "neon": "red", "prompt": "영어 장면 묘사"}]}]}
   ```
3. `shorts/why.sh render output/why/<슬러그>.json`을 실행한다(약 3~4분).
4. `sheet.jpg`를 Read로 보고 자막과 길이를 확인한다. 고칠 것이 있으면 spec을 고쳐 다시 render한다(최대 2번).
5. 미리보기 mp4는 SendUserFile로 보낸다. `prompts.md`의 위치와 함께 다음을 안내한다.
   - 컷마다 세로 영상을 만든다.
   - 파일 이름을 `C01.mp4`처럼 바꾸지 않아도 되고, 순서대로 올리기만 하면 된다.

### 대본 공식 (레퍼런스 분석)

1. 훅: 일상 현상에 "왜/어떻게"를 묻는다. ("지하철은 앞차와 몇 분 차이로 달리는데 어떻게 안 부딪힐까요?")
2. 통념 반박: "~해서가 아닙니다."
3. 숨은 원리: 보이지 않는 구조나 규칙을 공개한다.
4. 작동 과정: 원인→결과를 2~4단계로 이어 간다.
5. 일반화: "~마다 방식은 다르지만 원리는 같습니다."
6. 대구형 결론: "결국 A는 B가 아니라 C를 ~하는 겁니다."

분량과 사실 확인:
- 10~13문장, 컷 18~27개, 공백을 뺀 대본 약 300자로 쓴다. 이렇게 하면 내레이션 약 42초에 엔딩 카드를 더해 45초 안팎이 된다.
- 문장 하나를 컷 1~3개로 나눈다. 컷 자막은 15자 이하이고, 컷 자막을 이어 붙이면 그대로 내레이션이 된다.
- 사실만 쓴다. 웹 검색 도구가 있으면 핵심 사실(연도, 장치 이름, 수치)을 확인한다. 확실하지 않은 수치는 쓰지 않는다.
- 숫자, 단위, 영문 약어는 그대로 써도 자동으로 한글 읽기로 바뀐다. 애매하면 문장에 `"say"`(읽는 법)를 넣는다.

### 컷 프롬프트 규칙

- `prompt`는 영어 20~40단어로, 그 자막이 말하는 장면을 구체적으로 묘사한다. 피사체 하나, 카메라 움직임, 조명을 넣는다.
- `neon`에는 개념을 표시할 색 하나를 고른다. 위 색 의미를 영상 전체에서 일관되게 지킨다.
- `style`에는 모든 컷이 같은 세계처럼 보이도록 장소·소품을 영어로 쓴다(예: "inside a subway tunnel, steel rails").
  공통 시네마틱 스타일(사실적, 어두운 분위기, 젖은 반사면, 전진 카메라, 글자 없음)은 자동으로 붙는다.
- 레퍼런스 영상의 장면이나 대본을 그대로 베끼지 않는다. 구조와 기법만 참고한다.
- `handle`은 사용자의 채널명이다. 모르면 비워 둔다(워터마크 없이 엔딩 카드만 생긴다). 다른 채널 이름은 쓰지 않는다.
- 미리보기용으로 `icon`(Fluent 이모지 이름)을 넣으면 대체 장면 가운데에 보인다(선택).

## 2단계: 클립 업로드 → 완성본

1. 사용자가 올린 파일(`/root/.claude/uploads/...`)을 컷에 배정한다.
   ```bash
   shorts/why.sh add output/why/<슬러그>.json <올린 파일들...>
   ```
   - 파일 이름에 `C05` 같은 번호가 있으면 그 컷에, 없으면 빈 컷부터 올린 순서대로 넣는다.
   - 특정 번호부터 넣으려면 `--start 7`을 쓴다.
2. 다시 `shorts/why.sh render output/why/<슬러그>.json`을 실행한다. 클립은 이렇게 맞춘다.
   - 컷 길이에 맞게 자르고, 조금 짧으면 느리게, 많이 짧으면 반복한다.
   - 가로 영상은 세로로 꽉 차게 자른다.
   - 이미지는 천천히 확대한다.
   - 클립이 없는 컷만 네온 장면으로 남는다.
3. `sheet.jpg`로 컷과 자막이 맞는지 확인한다. 컷 순서가 틀렸으면 `add --start`로 다시 넣고 render한다.
4. 완성본을 SendUserFile로 보내고 경로를 알린다.

## 옵션

- `--voice N`: Supertonic 목소리를 고른다. 기본 8(남성), 0~4는 여성, 5~9는 남성이다.
- `--speed 1.2`: 말하기 속도를 바꾼다.
- `--bgm 파일.mp3`: 배경음악을 넣는다(음량 12%). 기본은 배경음악 없음이다. 저작권이 확실한 음원(예: YouTube 오디오 보관함)만 쓴다.
- Edge TTS에 접속되면 Edge TTS를 자동으로 쓴다.

## 전달

- 영상 경로와 길이
- 클립 몇 개가 들어갔는지
- 남은 컷 번호
- prompts.md 위치
