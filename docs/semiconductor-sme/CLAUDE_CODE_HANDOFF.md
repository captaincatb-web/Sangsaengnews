# 국내 상장 반도체 소부장 조사 — Claude Code 인계

## 목표
KOSPI·KOSDAQ·KONEX 전체 상장종목 모집단에서 국내 반도체 소재·부품·장비 기업을 식별하고, 기업 수·종목 수·시가총액·재무성과·공정별 공급망을 분석한다. 결과는 기존 정적 HTML/JS 대시보드와 연계한다.

## 먼저 읽을 기존 코드
- scripts/count_listed_semi.py
- scripts/build_market.py
- .github/workflows/semi-count.yml
- site/data/universe.js
- site/data/segments.js
기존 기능을 먼저 이해하고 재사용한다. 중복 수집기나 데이터 모델을 만들지 않는다.

## 현재 작업 데이터
- data/classification/direct_sme_candidates_20261101.csv: 직접 소부장 후보 110행. 원본 분류는 장비 46, 부품 37, 소재 27. 국내 상장기업으로 표시된 100행과 비상장/법인확인 유형 10행을 포함한다. 이 수치는 후보 마스터의 상태이며 최종 확정 수치가 아니다.
- data/market/krx_market_baseline_20261030.json: 사용자가 제공한 KRX 직전영업일 기준값.
- 사용자가 업로드한 2026-11-01 데이터 파일 2개(네이버 시세·시총, KRX 종목 기본정보)는 이 대화에서 종목코드 2,874개 집합이 일치함을 확인했다. 전체 원본 파일은 저장소에 올리지 않았으며, 필요 시 기존 수집기 또는 API로 재수집한다.

## 네이버증권 API 관찰
사용자가 확인한 주소:
https://stock.naver.com/api/domestic/market/stock/default?tradeType=KRX&marketType=KOSPI&orderType=marketSum&startIdx=0&pageSize=100
- KOSDAQ은 marketType만 KOSDAQ으로 바꾼다.
- startIdx=0과 1은 연속된 100건 페이지처럼 관찰됐으나 전체 규칙은 미검증이다.
- startIdx 0, 1, 2의 코드 교집합과 정렬 연속성을 테스트한 후 수집한다. 100씩 증가한다고 가정하지 않는다.
- 기존 스크립트의 pageSize=10/startIdx 자동 판별 로직과 새 endpoint를 비교해 테스트한다.
- marketSum 문자열은 안전하게 숫자화하고 null은 결측으로 유지한다. type 등 증권유형도 보존한다.

## 검증 원칙
1. 회사 수와 종목 수를 분리한다. 우선주·종류주권은 종목 수에 포함하고 회사 수는 발행회사 기준으로 중복 제거한다.
2. 종목코드는 6자리 문자열로 유지하고 ISIN·단축코드·주식종류·시장구분을 활용한다.
3. 직접 소부장, 조건부, 간접 공급망, 기타 반도체 산업을 구분한다. 팹리스·IDM·OSAT·유통사는 직접 소부장에 자동 편입하지 않는다.
4. 법인 분할·합병·지주사 전환·사명 변경을 검증한다. OCI와 OCI홀딩스 법인/종목코드 혼동은 근거 없이 수정하지 않는다.
5. 시가총액은 상장기업 전체 가치다. 반도체 사업부 가치로 표현하지 않는다. 반도체 사업 매출 비중은 별도 수집한다.
6. 결측·0·음수·적자·계산 불가를 구분한다.
7. 공개 저장소에 개인 연락처, 담당자/대표자, 내부 평가자료, API 인증정보를 추가하지 않는다.
8. 기준일·출처·수집시각을 기록한다. 분자와 분모의 기준일이 다르면 비중 계산을 확정하지 않는다.

## 작업 순서
1. 전체 2,874종목 코드·중복·시장별 수 검증, 회사 2,762개와의 차이 설명.
2. 후보 110개를 종목코드/법인 기준으로 재검증하고 미상장 10개는 별도 관리.
3. 직접 소부장 모집단 확정, 조건부/간접/기타는 별도 유지.
4. FAB/P&T/인프라 및 증착·식각·세정·열처리·CMP·검사·계측·본딩·패키징 공정 태깅.
5. 동일 기준일 시총 및 DART 재무지표 수집, 전사 매출과 반도체 사업 매출 분리.
6. 기존 정적 HTML/JS에 분석 화면 추가. 수집은 Python/GitHub Actions에서 수행.
