# 네이버증권 데이터 수집 가이드
작성 기준: 저장소의 `scripts/count_listed_semi.py` 구현을 읽고 사람이 이해하기 쉽게 설명한 문서

## 1. 한눈에 보기

현재 네이버증권 데이터는 이 프로젝트에서 주로 **국내 상장종목별 시가총액**을 가져오는 데 사용한다.

| 구분 | 무엇을 가져오나 | 어디에 쓰나 |
|---|---|---|
| KOSPI 종목 목록 | 종목코드, 종목명, 시가총액, 응답의 종목 유형 | 코스피 상장 종목별 시총 |
| KOSDAQ 종목 목록 | 종목코드, 종목명, 시가총액, 응답의 종목 유형 | 코스닥 상장 종목별 시총 |
| 반도체 업종 구성종목 | 네이버 업종 '반도체와반도체장비'에 속한 종목코드 | 네이버 업종 구성과 우리 소부장 분류 비교 |
| PC 웹 표(대체 경로) | 시가총액 순위 표의 종목코드·시총 | JSON API 수집 실패 시 대체 |

**주의:** 네이버 업종 '반도체와반도체장비' 구성종목은 네이버의 업종 분류다. 우리 프로젝트의 '직접 반도체 소부장' 확정 목록과 같은 개념이 아니다. 업종 구성 종목을 곧바로 소부장 기업으로 판정하면 안 된다.

## 2. 실제 호출 주소

### 2.1 KOSPI / KOSDAQ 시가총액 목록

기본 주소:

`https://stock.naver.com/api/domestic/market/stock/default`

프로젝트에서 사용하는 파라미터:

| 파라미터 | KOSPI 예시 | KOSDAQ 예시 | 의미 |
|---|---|---|---|
| `tradeType` | `KRX` | `KRX` | KRX 거래시장 기준 |
| `marketType` | `KOSPI` | `KOSDAQ` | 조회할 시장 |
| `orderType` | `marketSum` | `marketSum` | 시가총액순 정렬 |
| `startIdx` | `0`부터 | `0`부터 | 목록 위치/페이지 인자 |
| `pageSize` | `10` | `10` | 요청 건수. 현재 스크립트는 10으로 고정 |

예시 URL:

`https://stock.naver.com/api/domestic/market/stock/default?tradeType=KRX&marketType=KOSPI&orderType=marketSum&startIdx=0&pageSize=10`

KOSDAQ은 `marketType=KOSDAQ`으로 바꿔 호출한다.

### 2.2 응답에서 사용하는 필드

현재 코드가 읽는 핵심 필드는 다음과 같다.

| 응답 필드 | 사람이 이해할 이름 | 사용 방법 |
|---|---|---|
| `itemcode` 또는 `itemCode` | 종목코드 | 종목을 식별하는 기본 키. 문자열로 보존 |
| `itemname` | 종목명 | 진단 로그에서 예시로 확인. 현재 시총 결과 저장에는 별도 활용하지 않음 |
| `marketSum` | 시가총액 | 문자열의 쉼표를 제거해 숫자로 변환 |
| `type` | 종목 유형 | 현재 `ST` 또는 유형 미제공(`None`)인 행만 처리 |

**중요:** 현재 구현은 네이버 응답의 모든 필드를 저장하는 범용 수집기가 아니다. 위 필드 중 실제 시총 산출에 쓰는 것은 종목코드·시가총액·유형이다. 응답에 추가 필드가 오더라도 현재 코드가 자동으로 보존한다고 가정하지 않는다.

## 3. 시가총액 숫자는 어떻게 바뀌나?

현재 코드:

```python
ms = x.get("marketSum")
msv = float(str(ms).replace(",", "")) if ms not in (None, "") else 0
if msv > 0:
    out[sosok][x["itemcode"]] = round(msv / 1e8)
```

- 네이버 `marketSum` 값을 숫자로 읽는다.
- 현재 코드에서는 원 단위로 해석하고 `1억 원` 단위로 나누어 저장한다.
- 결과 자료구조의 값 단위는 **억 원**이다.
- 따라서 1조 원은 10,000억 원이다.

예시(단위 변환 설명용 가상 값):

| 네이버 응답 marketSum | 저장되는 값 | 사람이 읽는 값 |
|---:|---:|---:|
| 1,250,000,000,000 | 12,500 | 1조 2,500억 원 |
| 350,000,000,000 | 3,500 | 3,500억 원 |

실제 데이터 예시가 아니라 단위 변환을 설명하기 위한 예시다.

**개선 주의:** 현재 코드는 값이 없거나 숫자 변환에 실패한 경우 0으로 처리하고, 0보다 큰 값만 저장한다. 데이터 품질 분석에서는 '원본 null', '숫자 변환 실패', '실제 0', '양수'를 분리하는 편이 안전하다. 기존 동작을 바꿀 때는 downstream 계산과 대시보드 영향을 확인한다.

## 4. 페이지를 어떻게 넘기나?

현재 네이버 API의 `startIdx` 의미를 고정값으로 단정하지 않도록 스크립트가 첫 두 요청을 비교한다.

1. `startIdx=0`을 요청하고 종목코드 집합을 기록한다.
2. `startIdx=1`을 요청한다.
3. 두 응답의 종목코드 중복 여부로 페이지 방식 후보를 판별한다.
   - 두 응답이 같으면 페이지 번호 방식으로 보고 다음은 2, 3, 4…로 요청한다.
   - 일부 종목이 겹치면 offset 방식으로 보고 10, 20, 30…으로 요청한다.
   - 전혀 겹치지 않으면 0부터 시작하는 페이지 방식으로 보고 2, 3, 4…로 요청한다.
4. 이미 받은 종목코드는 중복 추가하지 않는다.
5. 응답이 비거나 새 종목이 0건인 상태가 반복되면 수집을 멈춘다.

현재 스크립트 기본값은 `pageSize=10`, 최대 400회 요청이다. 요청 사이에 0.15초 쉬고, HTTP 403·429 또는 리다이렉트가 발생하면 수집을 중단한다.

**주의:** 이것은 현재 코드에 구현된 페이지 추정 로직이지 네이버가 보장한 공식 페이지 규격이라는 뜻은 아니다. API 동작이 바뀔 수 있으므로 실행 로그의 수집 건수, 중복, 시장별 종목 수를 반드시 검증한다.

## 5. 종목 유형 필터

현재 코드에는 다음 조건이 있다.

```python
if x.get("type") not in (None, "ST"):
    continue
```

- `ST`: 현재 코드에서 일반 주식으로 처리하는 유형
- `None`: 응답에 유형 필드가 없으면 일단 통과
- 그 외 유형: 현재 시가총액 결과에서 제외

따라서 이 필터를 '모든 종류의 상장증권을 완전하게 포함한다'고 설명하면 안 된다. 우선주·종류주권·외국주권·ETF 등 실제 포함 여부는 KRX 종목 마스터와 대조해야 한다. 특히 `None`을 허용하므로 유형 미확인 행이 일반주식과 섞일 가능성도 별도 점검한다.

## 6. 네이버 반도체 업종 구성종목

호출 경로:

`/api/domestic/market/upjong/278/stocklist`

현재 파라미터:

- `marketType=KOSPI`
- `marketType=KOSDAQ`
- `orderType=marketSum`

업종번호 `278`은 현재 스크립트에서 '반도체와반도체장비' 업종으로 사용한다. 두 시장 응답을 합쳐 종목코드만 추출한다.

활용 목적:
- 네이버 업종 분류에 포함된 기업을 별도로 확인
- 우리가 직접 조사한 소재·부품·장비 후보와 비교
- 분류 누락 가능성이 있는 기업을 추가 검토 대상으로 찾기

제한:
- 네이버 업종은 기업의 주력 업종 분류일 수 있어 반도체 소부장 공급사 전체를 포괄한다고 볼 수 없다.
- 반대로 반도체 업종에 포함됐다고 해서 모두 소재·부품·장비 기업인 것도 아니다.
- 그러므로 업종 구성 종목은 **참고용 후보군**으로만 사용하고, 최종 소부장 판정은 기업별 제품·사업보고서·공정 적용 근거로 한다.

## 7. 수집 실패 시 대체 경로

JSON API 수집이 실패하면 현재 스크립트는 PC 웹 시가총액 표로 대체한다.

`https://finance.naver.com/sise/sise_market_sum.naver`

- `sosok=0`: KOSPI
- `sosok=1`: KOSDAQ
- 페이지 번호를 바꾸며 표를 읽는다.
- HTML에서 종목코드와 시가총액 칸을 추출한다.

대체 경로의 결과는 JSON API 결과와 수집 방식이 다르므로, 데이터 출처와 수집 방식을 결과 로그에 남긴다. 두 경로의 값이 같은 시점·같은 기준으로 수집됐다고 가정하지 않는다.

## 8. 프로젝트에서의 역할과 한계

네이버 데이터는 **종목별 시장 시가총액과 네이버 업종 구성 확인**을 위한 보조 원천이다.

| 분석 항목 | 네이버 데이터만으로 가능한가? | 추가로 필요한 데이터 |
|---|---|---|
| KOSPI/KOSDAQ 종목별 시총 | 가능(수집 성공 및 범위 검증 전제) | KRX 마스터로 종목 유형·상장 여부 대조 |
| 전체 상장기업 수 | 단독 확정 부적합 | KRX 상장종목/회사 마스터 |
| 소재·부품·장비 구분 | 불가 | 제품·사업보고서·기업별 검증 근거 |
| 반도체 사업 매출 | 불가 | DART 사업보고서/분기보고서 |
| 반도체 소부장 시장 비중 | 단독 확정 불가 | 확정 소부장 분자 + 같은 기준일 전체시장 분모 |
| 네이버 반도체 업종 포함 여부 | 가능(해당 업종 API 범위 내) | 업종 코드·수집 기준일 기록 |

시가총액은 상장회사 전체의 시장가치다. 다각화 기업의 경우 이 금액 전체를 반도체 사업가치라고 부르면 안 된다.

## 9. 수집 후 반드시 확인할 항목

매 실행마다 아래를 검증하고 로그/산출물에 남긴다.

- [ ] 조회 시장: KOSPI와 KOSDAQ 모두 성공했는가?
- [ ] 수집 출처: JSON API인지 HTML 대체인지?
- [ ] 수집 기준일/시각: 언제 수집했는가?
- [ ] 종목코드: 6자리 문자열로 보존했는가?
- [ ] 중복: 같은 종목코드가 중복 수집됐는가?
- [ ] 누락: KRX 종목 마스터와 비교해 빠진 종목은 무엇인가?
- [ ] 유형: `ST`, `None`, 기타 유형별 건수는 얼마인가?
- [ ] 시가총액: 원본 값과 억 원 변환값의 산식이 일치하는가?
- [ ] 결측: null·빈 문자열·변환 실패·0을 구분했는가?
- [ ] 기준일: 소부장 종목 시총과 전체시장 분모의 기준일이 같은가?

## 10. Claude Code 작업 지시

이 문서를 읽은 뒤 네이버 수집기를 수정하거나 확장할 때는 다음 순서를 지킨다.

1. 먼저 `scripts/count_listed_semi.py`의 `ns_pages`, `naver_caps`, `naver_upjong`, `naver_caps_html` 구현을 읽는다.
2. 테스트용 소수 종목으로 응답 구조와 페이지 동작을 확인한다.
3. KRX 종목 마스터와 종목코드·시장·증권유형을 대조한다.
4. API 응답 필드나 페이지 규칙이 달라졌으면 임의 추정 대신 진단 로그와 테스트를 추가한다.
5. 기존 JSON/HTML 대체 경로와 대시보드 데이터 계약을 깨지 않도록 회귀 테스트한다.
6. 수집 결과에는 출처·기준일·수집시각·단위·수집 건수·제외 건수를 기록한다.
7. API 키, 내부 데이터, 개인정보를 공개 저장소에 기록하지 않는다.
