# 국내·해외 소부장 성장 비교 — 산출 방법과 운영 안내

유지보수 담당자용 문서입니다. 기업명·등록번호·개별 재무는 이 문서에 적지 않습니다(비공개 자료는 파일 이름만 적습니다).

## 1. 목적
소재·부품·장비별로 국내와 해외 기업군의 매출 성장(2023=100 지수)과 영업이익률을 나란히 보여 줍니다. 공개 화면은 `site/growth-comparison.html`, 공개 데이터는 `site/data/growth-comparison-summary.json`(집계만) 한 파일입니다.

## 2. 집단 정의 (현재 기준: 2그룹)
| 집단(JSON 키) | 정의 |
|---|---|
| 국내(`dom`) | 소부장 경영 정보(대시보드)와 같은 기업군. 수요기업·IT·서비스 업종은 제외하고 업종(소재·부품·장비)은 그 화면의 분류를 그대로 씁니다. 상세구분1~5는 사용자 원본 목록과 연결된 법인에만 붙고(번호 일치 + 이름 보조 연결 + 승인된 보충), 없는 법인은 상세 필터에서 빠집니다(임의 분류 없음). |
| 해외계(`ov`) | ①사용자 목록(원본 해외 법인)과 사용자가 추가한 소부장 후보 중 **법인 본인의 공식 공시로 실적이 확인된 상장 본사**(비반도체 제외)와 ②**한국에 설립된 외국계 법인**(원본에서 '해외'로 표기, 한국 법인등록번호 보유; 이미 국내 기업군에 있는 법인은 제외)을 한 집단으로 합친 것입니다. 구성 건수는 요약 JSON `coverage.composition`에서 확인합니다. |

모집단 관계(건수는 모두 JSON·비공개 로그에서 확인하며 문서에 고정하지 않습니다):
원본 해외 법인 → (한국 법인번호가 있으면 한국 내 외국계로 분리, 법인등록번호로 같은 법인의 지점·공장 행을 묶음) → 추가 후보를 더함 → 적격 판정(비반도체 제외) → 법인 본인의 공식 공시로 3개년 매출·영업이익이 확인된 법인만 **균형 패널**로 집계 → 이중 집계 방지 규칙(아래)으로 일부 한국 자회사 제외 → 해외계.

**이중 집계 방지(한국 자회사 제외) 규칙** — 다음을 **모두** 만족할 때만 한국 자회사를 뺍니다.
1. 본사-자회사 관계가 **확인됨**: 근거 URL이 있는 검토 파일(`dedupe_overrides.csv`, decision=confirmed + evidence_url) 또는 법인 판정 CSV(모회사 공식명 + 근거 URL + 연결재무 포함=포함). 이름 접두 일치는 후보일 뿐이며 그것만으로는 제외하지 않습니다.
2. 본사가 3개년 균형 패널에 들어 있고,
3. 본사 재무가 **연결 기준**(자회사가 본사 실적에 포함됨).
본사가 개별 기준이거나 패널에 없으면 자회사를 유지합니다. 판정 근거는 비공개 `dedupe_log.csv`에 남기고 공개 JSON에는 건수만 둡니다.

대표 업종: 해외계 본사는 기업 전체 매출을 대표 업종 한 곳에만 반영합니다(원본 품목 분류로 중복 배분하지 않음). 한국 내 외국계는 원본 품목 분류를 따릅니다. 국내는 대시보드 업종 + 원본 상세구분을 씁니다.

## 2-1. 비교 모드 (요약 JSON `modes`)
| 모드 id | 비교 | 재무 범위 |
|---|---|---|
| `blend` | 국내 별도 vs 해외계 통합(참고용) | 국내 별도, 해외계는 개별 우선·미공시 시 연결(범위가 서로 다름) |
| `cons_listed` | 국내 연결 vs 해외 상장 본사 연결 | 양쪽 연결. 연결재무제표가 없는 기업은 별도로 **대체하지 않고** 제외, 해외는 연결 3개년이 확인된 상장 본사만 |
| `sep_kr` | 국내 별도 vs 한국 소재 외국계 별도 | 양쪽 별도(외국계는 사업·감사보고서, 억 원 반올림) |
모드마다 대상 기업 수·3개년 균형 패널·매출 합계·영업이익률을 따로 계산합니다. 서로 다른 재무 범위를 같은 기준이라고 표시하지 않으며 화면에 모드별 범위를 항상 보여 줍니다.
교차 역산 방지: 모드·집단·필터가 달라도, 같은 재무 기준 안에서 한 조합의 법인 집합이 다른 조합의 진부분집합이고 차이가 1~(k−1)곳이면 작은 쪽을 가립니다(`aggregate.cross_suppress`). 재무 기준이 다른 조합(국내 별도 vs 연결)은 개별 값이 드러나지 않으므로 비교하지 않습니다.

## 2-2. 법인 판정 CSV (조사 결과 반입)
`scripts/growth/ingest_entity_status.py`가 검증해 비공개 `entity_status.csv`로 만듭니다. 열: 원본그룹(A/B/C/신규), 목록표기, 공식법인명, 국가, 법인상태(상장 본사/상장 자회사/비상장 독립법인/비상장 자회사/지점/상장폐지/미확인), 상장폐지일, 거래소, 티커, 공시식별자, 모회사공식명, 모회사식별자, 연결재무포함여부, 소부장판정(포함/제외/보류), 대표업종, 근거URL, 근거위치, 확인일, 확신도, 추가조사필요.
규칙: 확정 판정(미확인 외 상태, 포함·제외)은 http 근거 URL 필수, 상장 본사·상장폐지는 거래소·티커·식별자 필요, 상장폐지는 상장폐지일, 자회사·지점은 모회사 공식명, 포함은 대표업종. 같은 목록표기에 공식법인명이 둘 이상이면 식별 충돌로 거부합니다(이름이 비슷하다고 합치지 않음). 조사 CSV에 없는 법인은 '미확인'으로 남기며 임의로 상장·비상장으로 확정하지 않습니다. 사용자 결정(`eligibility_overrides.csv`)이 판정 CSV보다 우선하고, 판정 CSV가 '비상장 자회사·지점'으로 본 법인의 재무 수치는 쓰지 않습니다(모회사 수치 대체 금지, `fin_guard_log.csv`).

## 2-3. 국가별 공시 수집기 (`scripts/growth/collectors/`)
모듈마다 `CAPABILITY`(implemented / live_verified / fixture_tested)를 가집니다. `live_verified`는 실제 Actions 실행으로 확인되기 전에는 False입니다. 접근 점검은 `probe_collectors.py`(소스당 GET 1회, 403·429는 기록 후 중단)로 하며 결과는 비공개 `collector_status.json`입니다. 2026-11-03 점검: 미국 SEC 접근 가능(인증 불필요, 기존 수집기는 실제 동작 확인), 일본 EDINET API v2는 구독 키(`EDINET_API_KEY`, 저장소 secret)로 실제 수집을 확인했습니다(`collect_edinet.py`: 유가증권보고서 재무 CSV에서 개별 우선 매출·영업이익 추출, 3·6·9·12월 제출 창 탐색). 2026-11-04 실행에서 대상 40곳 중 39곳의 문서를 받고 37곳이 3개년을 채웠으며, 조사 CSV와 겹친 56행은 값이 모두 일치했습니다, 대만 TWSE OpenAPI 접근 가능(최신 분기 한 건만 제공 → 3개년 이력 불가), 중국 CNINFO 호출 시 서버 오류(수집 불가·미검증), 유럽은 국가별 공시 소스가 달라 자리표시만 있고 수집 미구현.

### 해외 대상 확대 (2026-11-08)
- 해외 비교 페이지의 소부장 기업과 추가 발굴한 반도체 장비·소재·부품 주력 상장사를 넣었습니다(`extra_candidates.csv`, 근거 열에 출처 기록). 해외계 3개년 패널 154 → 181곳, 이어서 KLA 영업이익 계산값 반영으로 182곳(아래 데이터 출처의 예외 참고).
- 넣지 않은 곳과 이유: Corning·Resonac(반도체 매출 50% 미만 다각화 기업), Aixtron(공시 모음 미수록, 조사 필요), NAURA·AMEC(중국, 수집 경로 없음), ASMPT(홍콩, 수집 경로 없음).

### 다각화 기업 포함 기준 (2026-11-04 결정)
- 반도체 관련 매출이 법인 전체 매출의 **50% 이상**임이 공식 자료로 확인된 법인만 소부장 집계에 포함한다.
- 확인 전에는 "보류"로 두고 집계에서 제외한다(현재 Sumitomo Heavy, LINTEC, Kurita, Hamamatsu). 재무가 확보돼 있어도 같다.
- 반입 시 `eligibility_overrides.csv` 의 사용자 결정이 `entity_status.csv` 판정보다 우선한다.

## 3. 데이터 출처
- **국내**: DART 개별(별도, OFS) 재무제표. 대시보드와 같은 수집기(`scripts/build_financials.py`)를 비공개 Actions에서 돌려 얻습니다.
- **국내 소재 외국계**: DART 사업보고서 개별 재무 → 없으면 감사보고서 원문(`scripts/growth/collect_audit.py`). 감사보고서 값은 억 원 단위로 반올림되어 있습니다.
- **해외(미국·SEC 제출사)**: SEC 10-K·20-F XBRL. 기존 목록은 `collect_sec.py`(이름 정확 일치·확인된 티커), 추가 대상은 `collect_sec_tickers.py`(대상 목록의 티커와 SEC 티커가 정확히 같을 때만). 영업이익 항목(OperatingIncomeLoss 등)을 공시하지 않는 회사는 다른 항목으로 계산하지 않고 비워 둡니다.
  - 예외(사용자 승인 2026-11-08): 대상 목록의 `영업이익계산` 열에 표시한 법인(현재 KLA 1곳)만 `매출 − 매출원가 − 연구개발비 − 판관비`로 계산합니다. 네 항목이 같은 연차보고서(접수번호)·같은 회계기간·같은 통화일 때만 계산하고, 하나라도 없거나 다르면 비웁니다.
  - 따로 공시된 영업권·무형자산 손상, 구조조정 비용은 더하거나 빼지 않습니다. KLA는 2024·2025 회계연도에 영업권·무형자산 손상(각 약 2.9억·2.4억 달러)이 있어, 그 해 계산값은 손상을 반영한 영업 결과보다 높습니다(영업이익률로 약 2~3%p).
  - 공개 화면의 회사별 목록에 `영업이익 계산값`으로 표시하고, 집계 주석에도 적습니다.
- **해외(일본)**: EDINET 유가증권보고서 재무 CSV(`collect_edinet.py`). 제출 시기는 결산월+3개월째 달로 잡습니다(1·2월 결산 법인 포함). 개별 우선이지만 **지주회사는 개별 재무가 배당 등 지주 수익 위주라 사업 실적이 아니므로 연결로 지정**합니다(대상 목록 `기준` 열; SCREEN Holdings, Ferrotec).
- **해외(유럽)**: ESEF 공시 모음(filings.xbrl.org, `collect_esef.py`). 공시 등록명이 공식 법인명과 같을 때만(악센트·법인격 표기 차이는 무시) 연결합니다. 표준(ifrs-full) 매출·영업이익 개념을 우선하고, 없을 때만 회사 자체 항목명(확장 개념)의 차원 없는 연간 총액을 쓰며 확신도를 '중간'으로 표시합니다. 독일 상장사 일부(Aixtron, Siltronic, SUSS)는 이 공시 모음에 없습니다.
- **해외(대만)**: FinMind 재무제표 데이터(대만 공시 원천)의 분기 매출·영업이익 4개를 합산(4개 분기가 모두 있을 때만)(`collect_finmind.py`). 연결 기준. 공시 수치와 대조(예: 鴻海 2023 매출 6.16조 대만달러, GlobalWafers 2024 매출 626억 대만달러 일치).
- **해외(그 외)**: 공식 공시 원문을 조사한 CSV를 반입기 `scripts/growth/ingest_overseas_csv.py`로 검증·환산해 씁니다.
- **환율**: ECB 일별 교차환율(통화→원)의 해당 회계기간 평균. ECB가 발표하지 않는 대만달러(TWD)는 臺灣銀行 고시 달러 현물 매입·매도율의 중간값(1달러당 대만달러, FinMind 경유)과 ECB 원/달러를 같은 날짜끼리 교차한 값의 회계기간 평균을 씁니다(예비: 미국 연준 H.10). 환율을 받지 못한 통화는 원화 환산을 비우고 집계에서 뺍니다.

## 4. 계산 규칙
- **회계연도**: 회계기간 종료일의 연도. 기간은 350~380일이어야 하고, 매출과 영업이익은 같은 회계기간일 때만 함께 씁니다. 2023·2024·2025년에 끝나는 기간 3개가 모두 있어야 합니다.
- **동일 기업군(Balanced Panel)**: 2023~2025년 매출·영업이익이 모두 확인된 적격 법인만 집계에 넣습니다.
- **영업이익률** = 영업이익 합계 ÷ 매출 합계(기업별 이익률의 평균이 아님).
- **성장률** = 당해 ÷ 전년 − 1. 2023년 성장률은 2022년 매출이 모든 법인에서 확인될 때만 계산합니다.
- **매출지수** = 해당 집단 합계의 2023년 값을 100으로 한 지수.
- **재무 기준**: 국내와 한국 내 외국계는 별도(개별). 해외 본사는 개별을 우선하고, 개별이 공시되지 않으면 연결을 쓰되 화면에 표시합니다(미국 SEC 등록 법인과 20-F 제출사는 대부분 연결). 한 법인의 3개년은 같은 기준으로 통일합니다(개별로 3개년이 완전하면 개별, 아니면 연결로 완전할 때 연결). 기준이 달라 직접 비교에 한계가 있다는 안내를 화면에 표시하며, 계산 가능한 수치를 이유로 삭제하지 않습니다. 연결·개별이 섞인 법인은 반입기가 법인 전체를 거부합니다.
- **값이 없으면** 빈 값입니다. 추정·보간·모회사 대체를 하지 않습니다.

## 5. 공개 안전 규칙
- 집단(국내·해외계)마다 법인 수가 `k_min_per_side`(기본 5) 이상일 때만 그 집단 값을 공개합니다.
- **부분집합 차이 방지**: 공개되는 두 조합 X ⊃ Y(같은 집단, 그래프분류 '전체' ⊃ 개별 분류, 상세구분 경로가 접두 관계)에서 |X − Y| < k이면 Y를 가립니다. 안정될 때까지 반복합니다(`scripts/growth/aggregate.py` `publishable`).
- 공개 JSON에는 집계값·건수·필터 조합만 담습니다. 기업명, 등록번호, 개별 재무, 품목 매핑, 원본 행, 거래관계는 담지 않습니다. `tests/test_growth_public_safety.py`가 이를 검사합니다.

### 회사별 상세 공개 (2026-11-04 사용자 승인)
- `site/data/growth-companies.json`: 비교 기준별로 3개년 동일 기업군에 포함된 법인의 회사명·분류·재무 기준·매출·영업이익(억 원)을 법인별로 공개한다. 집계에서 빠진 법인(보류·제외·실적 미확인)은 싣지 않는다.
- 법인등록번호·사업자등록번호·내부 식별자와 원본 740행은 싣지 않는다. 회사명의 법인격 표기((주) 등)는 제거한다.
- 회사별 수치가 공개되므로 5곳 미만 집계 비공개(k-익명)는 보호 효과가 없다. 집계 셀 비공개 규칙은 일관성을 위해 유지한다.
- 점검: `tests/test_growth_companies_public_safety.py`(필드 허용 목록, 10자리 이상 숫자·법인격 표기 없음, 집계 패널과 법인 수 일치).

## 6. 비공개와 공개의 경계
| 구분 | 위치 | 내용(파일 단위) |
|---|---|---|
| 비공개 작업 폴더 | 저장소 밖 `GROWTH_PRIVATE_DIR` | `master_rows.csv`(원본 정제), `domestic_match.csv`, `domestic_financials.csv`, `roster_financials.js`, `roster_class.json`, `ovkr_match.csv`, `ovkr_financials.csv`, `ovkr_audit_financials.csv`, `sec_match.csv`, `overseas_financials.csv`, `overseas_financials_ext.csv`, `eligibility_overrides.csv`, `roster_detail_overrides.csv` |
| 비공개 저장소 | Internal 저장소 `data/growth/` 이하 | 위 파일의 원본·결과 사본, 조사 CSV 입력(`ext/`), 외국계 입력·결과(`ovkr/`) |
| 비공개 워크플로 | Internal 저장소 `.github/workflows/` | `growth-domestic`, `growth-overseas`, `growth-overseas-kr`, `growth-overseas-audit`, `growth-roster`, `growth-ingest`(모두 수동 실행, 로그에는 건수만 출력) |
| 공개 | 이 저장소 | `scripts/growth/*`(코드), `site/growth-comparison.*`(화면), `site/data/growth-comparison-summary.json`(집계), 테스트, 이 문서 |

비공개 폴더 경로가 저장소 안이면 `validate_master.py`·`collect_domestic.py`는 실행을 거부합니다(비공개 저장소 실행 때만 `GROWTH_PRIVATE_REPO=1`).

## 7. 갱신 절차
1. (필요 시) Internal에서 수집 워크플로를 실행합니다: `growth-domestic` → `growth-roster` → `growth-overseas`(SEC) → `growth-overseas-kr` → `growth-overseas-audit`. 키는 저장소 secret(`DART_API_KEY`, `SEC_USER_AGENT`)으로만 둡니다.
2. 해외 조사 CSV가 새로 오면 필수 열을 확인합니다: 목록표기, 공식법인명, 상장여부, 거래소, 티커, 결산월, 회계연도, 기간시작, 기간종료, 통화, **금액단위**(1·천·백만·억 등), 매출, 영업이익, 연결/개별, 출처URL, 쪽/표위치, 확신도, 비고. 출처 URL·금액단위가 없거나 회계기간이 1년이 아닌 행은 반입기가 거부합니다. `growth-ingest`로 환산합니다.
3. 결과 파일을 비공개 작업 폴더로 받은 뒤 `GROWTH_PRIVATE_DIR=<경로> python scripts/growth/build_growth_comparison.py`를 실행해 요약 JSON을 만듭니다.
4. `python3 -m unittest discover -s tests`로 검증합니다(집계 규칙, 반입기, 공개 안전 검사).
5. `GROWTH_PRIVATE_DIR=<경로> python scripts/growth/verify_growth.py`로 요약 JSON을 법인 자료에서 독립적으로 다시 계산해 대조합니다(기업 수·합계·영업이익률·성장률·원화 환산·구성 메타, 출력은 통과/실패와 건수뿐).
6. 요약 JSON과 코드만 커밋해 PR로 올립니다. 병합·배포는 검토 후에 합니다.

## 8. 데이터 기준일·재집계
요약 JSON의 `generatedAt`이 생성 시각입니다. 회계연도는 2023~2025(회계기간 종료일 기준)이며 최신 사업·연차보고서에 따라 달라질 수 있습니다. 신규 재무 자료가 들어오면 7장 절차로 재집계하고, 집계 대상(균형 패널)과 미조사·보류 법인은 `coverage`와 비공개 보고서로 구분합니다.

## 9. 알려진 한계
- 해외계 안에서 개별과 연결 재무가 법인별로 섞여 있고 국내는 별도 재무여서 매출 규모·수익성을 같은 기준의 직접 비교로 해석할 수 없습니다.
- 해외는 공시 접근성과 재무 확보 가능성으로 선택된 일부 표본이라 해외 산업 전체를 대표하지 않습니다. 해외 분류별 값은 5곳 미만이면 공개하지 않습니다.
- 외국계는 감사보고서에서 읽은 억 원 단위 반올림 값이라 작은 법인은 정밀도가 낮습니다.
- ECB 미제공 통화(TWD 등)는 원화 환산을 비워 집계에서 빠집니다.
- 기업 전체 매출 기준이며 반도체 사업 매출이 아닙니다.
- KRX·네이버·Yahoo 시세의 공개 재배포 약관은 아직 확정되지 않았습니다(법적 확인 필요). 이 비교 화면은 시세를 쓰지 않지만 사이트의 다른 화면에는 영향이 있습니다.
